## F6 — VIN (PRD §4 F6)
- **vPIC** `https://vpic.nhtsa.dot.gov/api/vehicles/DecodeVinValues/<VIN>?format=json` (documented at
  https://vpic.nhtsa.dot.gov/api/Home/Index). Free, no key or account. Terms on that page: "Users/Applications attempting
  to use vPIC APIs will be controlled by an automated traffic rate control mechanism"; batch decode max 50 VINs.
- **Browser CORS: allowed.** GET and the OPTIONS preflight return `access-control-allow-origin: *`; a real browser
  fetch from a page at http://127.0.0.1 decoded 1HGCM82633A004352 → HONDA Accord 2003, ErrorCode 0. So the
  user-initiated decode (button "Decode with NHTSA", after the notice "Decoding sends this VIN to NHTSA's vPIC
  service.") ships; the VIN goes only to vPIC, with `credentials: "omit"` and `referrerPolicy: "no-referrer"`.
- **VIN-specific unrepaired-recall status: no documented, authorized public interface.** api.nhtsa.gov documents
  recalls by make/model/year and by campaign number only; the VIN lookup at https://www.nhtsa.gov/recalls is a web page
  whose backend is undocumented (and nhtsa.gov answers scripted requests with 403). We do not reverse-engineer it.
  In-app status = `blocked(no documented authorized interface)`; the app hands off to https://www.nhtsa.gov/recalls.

## F9 — Photon Spectrum (Stable docs, https://photon.codes/docs/llms.txt → llms-full.txt)
- **SDK:** `spectrum-ts` (TypeScript/Bun/Node). Runtime send/receive is SDK-only; the REST "Spectrum API" is the
  management plane (projects, webhooks, lines). → F9 needs a small TS sidecar behind HTTP (A's prompt allows it).
- **Auth:** `projectId` + `projectSecret` for the SDK; webhook signing secret per webhook (shown once).
- **Inbound:** either the SDK loop (`for await (const [space, message] of app.messages)`) or webhooks: POST with
  `X-Spectrum-Event`, `X-Spectrum-Signature: v0=<hmac>`, `X-Spectrum-Timestamp`, `X-Spectrum-Webhook-Id` (dedupe).
  Signature = HMAC-SHA256 over `v0:<timestamp>:<rawBody>` (raw bytes), 5-minute replay window; bad → 401. Up to 6
  delivery attempts with backoff on 5xx/408/429.
- **Outbound / limits:** 5,000 outbound messages per server per day (hard; Apple ban risk), 50 new conversations per
  line per day, management API 5 requests/s per project. Docs: iMessage is for warm conversations, not cold outreach
  (fits our user-initiated enrollment).
- **Attachments:** `attachment(path | URL | Buffer, {mimeType})` via the SDK; webhooks carry attachment metadata only.
- **Price / account:** plans pro / business / enterprise via Stripe (CLI `photon billing`); what our account has
  (project, line) is unknown to A → Gate P input for D/humans.
